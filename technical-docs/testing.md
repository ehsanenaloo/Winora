# Testing and release

Build Release solution and run focused unit/integration tests in Windows CI. Tests write only application-owned temporary directories; no Windows mutations, elevation or uninstallers on host. Cover preparation persistence failure, crash reconciliation, idempotency, external drift rollback, shared resource overlap, malformed profiles/protocol and localization fallback. SQLite tests use actual database files and close/reopen.

No test run proves production Windows mechanisms or accessibility. Future privileged tests are opt-in disposable VM jobs; require snapshots, user/machine scope, restart, edition/build/hardware matrix and malicious IPC cases. Release gates: authentic GPLv3, SPDX headers, dependency notices/lock review, threat review, signed worker trust, reproducible build/package, clean-machine install/uninstall, migration backup, screen reader/keyboard/high contrast/RTL/DPI and explicit unsupported results. Current version 0.1.0 is a foundation, not an optimizer release.

M1 discovery tests: `tests/Winora.Cli.Tests` (xunit) covers argument parsing, JSON schema and key order, filter/limit, exit-code rule, cancellation (130), no raw exception text, control-character neutralization and Persian output using fake `IDiscoverySource<T>` implementations, plus child-process runs of the built CLI against real read-only discovery. Process tests assert shape and the exit rule only, never specific machine content. a development tool that is not published adds the same smoke checks. Adapter fixture tests live with the adapters. Real-host runs are read-only and are reported as smoke evidence, not as correctness proof for other machines.

M2 Desktop and CLI tests (no real registry, shell or session): a test script of the development repository drives the real Customize and History views with `FakeSettingsService` (in-memory, records every call), `ScriptedPrompt` (answers the review dialogs) and `FakeWindowsSession`; the harness replaces `ISettingsService`, `IRegistrySettingsAccess` and `IWindowsSession` through the `App.BuildServices` configure hook, a test asserts the composition holds no real registry type, and the default prompt denies. `SettingsScreenshotTests.cs` renders `artifacts/ui-m2-*.png` when `WINORA_TEST_ARTIFACTS` is set. a test script of the development repository covers parsing, formatting, JSON shapes, exit codes and the no-write-without-`--yes` rule with a fake service; `SettingsProcessTests.cs` launches the built CLI against a temp journal and the hidden sandbox root `HKCU\Software\WinoraTests\<guid>` (deleted on dispose). Nothing in these tests restarts Explorer, broadcasts or signs out.

Single instance and jump list: a test script of the development repository and `LauncherTests.cs` run the real pipe server and client in the test process under the current user (unique pipe names, no machine state) and cover refusal of unknown, malformed, oversized, too frequent, other-session and other-user input. a test script of the development repository covers the command line, the jump list entries and the window side. The jump list of the test host is never written: the tests build the list object and do not apply it. A real hand-over from a medium integrity launcher to an elevated app runs only on the VM (a test script of the development repository).
